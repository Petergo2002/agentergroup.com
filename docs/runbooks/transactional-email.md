# Transactional email — design system, Resend and Supabase Auth

Every email Avenro sends renders through one design system in `src/lib/email/`.
The app's own emails go out over Resend; signup, magic link, password reset and
email change are sent by Supabase Auth from HTML generated by the same code.

## What is where

| Path | Purpose |
| --- | --- |
| `src/lib/email/theme.ts` | Brand tokens, logo paths, asset-origin resolution |
| `src/lib/email/html.ts` | `h` tagged template, `escapeHtml`, `safeUrl` |
| `src/lib/email/components.ts` | Chip, heading, paragraph, button, detail rows, quote, code block |
| `src/lib/email/layout.ts` | Preheader, logo header, card, footer, dark mode, Outlook fallbacks |
| `src/lib/email/copy.ts` | English and Swedish copy for every email |
| `src/lib/email/templates/` | One file per email; each returns `{ subject, html, text }` |
| `src/lib/email/index.ts` | Resend client, `sendInviteEmail`, `sendLeadNotificationEmail` |
| `supabase/templates/<locale>/` | **Generated.** Supabase Auth templates — never edit by hand |
| `public/email/` | The PNG logos the emails load |

## Working on the design

```bash
npm run email:preview
```

Writes every email, in both languages, with sample data to `.email-preview/`
(gitignored) with the logo inlined so the files open straight in a browser or
paste into Litmus. Open `.email-preview/index.html`.

After a design or copy change, regenerate the Supabase templates:

```bash
npm run email:templates
```

`tests/email/templates.test.ts` fails if the committed templates drift from the
design system, so this step is not optional.

## Rules the templates follow

These are the things that break in real inboxes, so keep them when adding an email:

- **Tables and inline styles only.** Outlook on Windows renders with Word's HTML
  engine: no flexbox, no grid, no CSS custom properties.
- **600px maximum width**, with a `<!--[if mso]>` ghost table around it.
- **A preheader.** The hidden `.preheader` div is what Gmail shows next to the
  subject. Write a distinct sentence — never repeat the subject.
- **A plain-text part.** Resend gets `text` on every send; HTML-only mail is
  scored down by spam filters.
- **A VML button.** Outlook ignores `border-radius` and padding on anchors, so
  `button()` ships a `v:roundrect` next to the normal anchor.
- **A pasteable link under the button**, for clients that strip the button.
- **Logos as PNG, not SVG.** Gmail and Outlook drop SVG. Two files are shipped —
  dark wordmark for light backgrounds, white wordmark for dark mode — and the
  swap is a CSS class toggle in the dark-mode block.
- **Dark mode twice**: `prefers-color-scheme` for Apple Mail and iOS, plus
  `[data-ogsc]` for Outlook.com, which rewrites the document instead.
- **Contrast.** Small footer copy uses `#6b7484`, not the app's lighter tertiary
  grey, and links use `#c2410c` — brand `#ff5c02` only reaches 3.1:1 on white.
- **Escaping by default.** Interpolate through the `h` tagged template; only
  markup wrapped in `raw()` is passed through.

## Environment variables

```dotenv
RESEND_API_KEY=re_...
EMAIL_FROM_ADDRESS="Avenro <noreply@avenro.se>"
EMAIL_REPLY_TO_ADDRESS=info@avenro.se
EMAIL_ASSET_BASE_URL=https://avenro.se
EMAIL_POSTAL_ADDRESS="Avenro, Street 1, 111 11 City, Sweden"
```

`EMAIL_ASSET_BASE_URL` is where the logo is loaded from. It defaults to
`NEXT_PUBLIC_APP_URL`, falling back to `https://avenro.se` when that is
localhost — a mail client cannot reach your dev server, so without the fallback
every test send arrives with a broken image.

`EMAIL_POSTAL_ADDRESS` is currently unset, so the footer omits the address line.
A postal address is required by CAN-SPAM for promotional mail and is expected by
most inbox providers; set it before sending anything that is not strictly
transactional.

Lead notifications set `replyTo` to the lead's own address, so the owner can
answer straight from their inbox. Everything else replies to
`EMAIL_REPLY_TO_ADDRESS`.

## Installing the Supabase Auth templates

Supabase hosts its own templates, so the generated HTML has to be pasted into
the project — committing it is not enough.

1. Open **Supabase → Authentication → Emails → Templates**.
2. For each template below, paste the file contents into the message body and
   set the subject. Keep `{{ .ConfirmationURL }}` and `{{ .Token }}` exactly as
   they appear.

   | Supabase template | File | Subject |
   | --- | --- | --- |
   | Confirm signup | `supabase/templates/en/confirmation.html` | Confirm your email address |
   | Magic Link | `supabase/templates/en/magic-link.html` | Your Avenro sign-in link |
   | Reset Password | `supabase/templates/en/recovery.html` | Reset your Avenro password |
   | Change Email Address | `supabase/templates/en/email-change.html` | Confirm your new email address |
   | Reauthentication | `supabase/templates/en/reauthentication.html` | Your verification code |

   Swap `en` for `sv` to send Swedish instead. Supabase supports one language
   per project, so pick the one that matches most of your signups.

3. Under **Authentication → URL Configuration**, confirm the Site URL is
   `https://avenro.se` and that `https://avenro.se/**` is in the redirect
   allow-list. `{{ .ConfirmationURL }}` carries the `emailRedirectTo` that
   `src/app/login/actions.ts` sets, and the link dies without the allow-list
   entry.
4. Set **Project Settings → Authentication → SMTP** to Resend, otherwise these
   go out from Supabase's shared sender with a low hourly cap:

   ```
   Host: smtp.resend.com
   Port: 465
   Username: resend
   Password: <RESEND_API_KEY>
   Sender email: noreply@avenro.se
   Sender name: Avenro
   ```

`supabase/config.toml` already points the local stack at the English templates,
so `supabase start` picks them up without any extra setup.

## Before the first real send

- Verify `avenro.se` in Resend and publish the SPF, DKIM and DMARC records it
  asks for. Without them Gmail and Outlook will junk the mail regardless of how
  it looks.
- Deploy once so `https://avenro.se/email/avenro-logo.png` resolves — the logo
  is loaded from the live site, not attached.
- Send one of each to a Gmail, an Outlook.com and an Apple Mail address, and
  check both light and dark mode.
